## 화면과 꽃

- DOM: 초기·입력 오류·성공·롤백 × 1440×900·390×844를 기준 HTML과 직접 비교했습니다. 초기와 오류 화면은 픽셀 차이 0, 결과 화면의 최대 차이 비율은 약 0.002%로 0.1% 기준 이내입니다.
- 글꼴: Chromium의 실제 렌더링 폰트 검사로 한글 제목이 IBM Plex Sans KR을 사용하는지 확인했습니다.
- 꽃: 원본 r128과 앱 r186의 초기·성공·롤백 화면에서 형태·크기·위치·색·시듦을 비교했습니다. 난수로 입자 위치가 달라지므로 원본과의 총 밝기 비율도 확인했으며 차이는 약 1% 이내였습니다. 밝기 검사 자체의 허용 범위는 ±20%이며, 이것만으로 시각 동등성을 판정하지 않습니다.
- 수식: 고정 난수에서 꽃과 먼지의 모든 attribute 배열이 원본과 일치합니다. 셰이더는 두 색의 uniform 변경을 제외하면 원본과 동일합니다.
- 모션: 3.2초 인트로의 중간·완료 상태, 1.4초 히어로 등장, 포인터 방향·계수, 리사이즈 배치, 감쇠와 reduced motion을 확인했습니다. 프로덕션 브라우저에서도 흩어진 입자→꽃, 포인터 반응을 캡처해 확인했습니다.
- 배포: 진행률·시듦 1→0.85·재시작 0과 먼지의 공유 uniform을 검사했습니다. 성공·롤백·재시작 중 canvas가 유지되고, reduced motion 재시작 후 꽃 영역이 초기 이미지와 일치합니다.
- 수명주기: 씬 10회 생성·해제, 이미지 로드 중 해제, StrictMode에서 새 canvas 사용, 개발 모드 10회 반복 진입에 컨텍스트 경고가 없는 것을 확인했습니다.
- 모바일: Chromium 390×844·844×390, WebKit 390×844·844×390에서 가로 넘침 없이 폼·성공·롤백·재시작이 동작했습니다.

## 성능

Chromium 로컬 실행에서 180개 프레임 간격을 측정했습니다. 중앙값 16.7ms, p95 16.8ms, 평균 약 59fps였습니다. 개발 모드와 headless 브라우저에서 측정한 값이며 기기별 성능 보장은 아닙니다.

실제 브라우저의 꽃 입자는 데스크톱 약 46,400개, 모바일 약 29,400개입니다. 먼지는 각각 1,400개·600개입니다. 꽃 입자 수는 난수에 따라 조금 달라집니다. 모바일 여부는 씬 생성 시 한 번 판정해 원본과 동일하게 유지합니다.

## 기준 문서와 구현의 차이

- `.git/` 입력: 원본은 `.git` 제거 후 끝 `/`를 제거하므로 `o/r.git/`가 `o/r.git`로 파싱됩니다. 원본을 유지했습니다.
- reduced motion: 모든 성공 스텝이 이미 300ms보다 짧아 성공 총 시간은 줄지 않습니다. 롤백의 1,400ms 대기는 300ms로 줄어듭니다.
- JavaScript 타이머의 소수 ms 절삭으로 누적 시간에 작은 차이가 생깁니다. fake timer 검사는 이 차이를 고려해 ±50ms 이내로 검증합니다.
- CSS 최적화는 UI 색을 짧은 hex로 줄일 수 있습니다. 리더는 이를 지원하고, 꽃의 퍼센트 채널은 별도 변수로 보존해 hex 반올림을 방지했습니다.
- 체크박스는 원본 기본 여백과 light 색상 스킴을 명시해 Tailwind 초기화·페이지 dark 스킴 차이를 보정했습니다.
- 생성·정리가 반복되는 StrictMode에서는 canvas도 새로 만들어 해제된 WebGL 컨텍스트를 재사용하지 않습니다.
