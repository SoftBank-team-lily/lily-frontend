# 꽃에서 대시보드로 진입하는 전환 계획

상태: **계획 작성 — 구현 전**

## 1. 목표

꽃을 클릭하면 카메라가 꽃술로 가까워지면서 화면 중심에 꽃술이 들어오고,
꽃 안으로 들어가는 느낌으로 `lily-dashboard`에 진입할 수 있는 연결점을 만듭니다.
대시보드 UI, 인증, 실제 배포 API는 이번 범위에 포함하지 않습니다.

`lily-dashboard`는 연결할 대상의 이름으로 취급합니다. 저장소 이름인지,
같은 앱의 경로인지, 외부 URL인지는 아직 확정하지 않습니다.

## 2. 사용자 흐름

1. 꽃 위에 마우스를 올리면 커서만 손 모양으로 바뀝니다. 테두리·배경·hover 박스는 표시하지 않습니다.
2. 꽃 클릭 또는 키보드 Enter/Space로 진입을 시작합니다.
3. 꽃의 마우스 기울임을 고정하고, 랜딩 문구·폼을 서서히 감춥니다.
4. 카메라가 꽃술을 화면 중앙에 맞추면서 가까워집니다.
5. 마지막 구간에서 검은 배경으로 짧게 페이드합니다.
6. 확대가 완료되면 `onEnterDashboard`를 정확히 한 번 호출합니다.
7. 나중에 이 콜백에 실제 경로 이동을 연결합니다.

**연결 전 동작:** 콜백이 없다면 “대시보드 연결 준비 중입니다.”를 알리고,
카메라와 랜딩을 원래 상태로 복구합니다. 빈 대시보드 페이지나 404로 이동하지 않습니다.
이 임시 안내는 대시보드 화면이 아니라 랜딩의 작은 상태 메시지입니다.

### 클릭 가능한 상태

- 기본 계획은 배포 완료 여부와 관계없이 꽃이 조립된 후 진입할 수 있도록 합니다.
- 배포 진행·실패 처리 중에는 진입을 잠시 막아 두 연출이 충돌하지 않게 합니다.
- 배포 전 진입에서는 연결 콜백에 배포 결과를 전달하지 않습니다.
- 성공 또는 롤백 후 진입에서는 현재 배포 결과를 전달합니다.
- 로딩 중이거나 WebGL을 사용할 수 없다면 줌 없이 같은 연결점을 실행할 수 있는
  텍스트 버튼을 제공합니다.

## 3. 현재 코드에서 바꿀 부분

| 현재 구조 | 추가할 동작 |
|---|---|
| `FlowerCanvasClient`의 전체 화면 캔버스는 `pointer-events-none` | 꽃 영역에만 별도의 의미 있는 버튼 배치 |
| `FlowerScene`이 RAF·카메라·포인터를 관리 | 같은 RAF에 진입/복귀 애니메이션 추가 |
| `fitView`는 꽃 전체를 랜딩 슬롯에 맞춤 | 초기 뷰로 유지하고 꽃술용 목표 뷰를 별도로 계산 |
| `LandingPage.onComplete`는 배포 종료 이벤트 | 클릭 진입용 `onEnterDashboard`를 별도로 추가 |

배포 완료와 사용자의 대시보드 진입은 서로 다른 이벤트입니다.
기존 `onComplete`에서 자동 이동하지 않고, 꽃 클릭 후 확대가 끝난 순간 연결합니다.

## 4. 카메라 연출

### 꽃술의 위치

파티클 생성은 `PARTICLES.centerX/centerY`를 기준으로 좌표를 만들기 때문에
꽃술은 로컬 좌표의 `(0, 0)` 부근에 있습니다. `FLOWER.cx/cy`는 꽃 전체를
화면에 맞추기 위한 중심이므로 줌 목표로 그대로 사용하지 않습니다.

- 꽃술 목표는 우선 로컬 `(0, 0, -0.45)` 부근으로 둡니다.
- 실제 깊이는 마스크 밝기·입자 편차에 따라 달라지므로 브라우저에서 조정합니다.
- 꽃 그룹의 현재 회전을 적용해 로컬 목표를 월드 좌표로 변환합니다.
- 클릭 순간의 회전을 고정해 줌 중 목표가 포인터를 따라 흔들리지 않게 합니다.

### 이동 방식

- CSS로 캔버스를 확대하지 않고 `PerspectiveCamera`의 위치와 바라보는 점을 보간합니다.
- 시작값은 클릭 순간 실제 카메라 값으로 잡아 리사이즈·스크롤 이후에도 튀지 않게 합니다.
- FOV는 유지하고 카메라 거리를 줄여 입자 사이로 가까워지는 깊이감을 만듭니다.
- 목표 거리는 화면 비율과 꽃술 반경으로 계산합니다. 데스크톱·모바일에서 꽃술이
  화면의 중심 영역을 채우도록 맞추고, 카메라가 입자를 통과하기 전에 페이드합니다.
- 초안 시간: 확대 **1,200ms**, 랜딩 숨김 **250ms**, 마지막 페이드 **200ms**.
- 초안 곡선: 부드러운 시작·종료의 cubic easing. 수치는 실제 화면 확인 후 조정합니다.
- 새 애니메이션 루프나 WebGL 컨텍스트를 만들지 않습니다.

전환 중 resize는 현재 진행률을 보존하면서 목표 뷰만 새 화면 비율에 맞춥니다.
일반 `fitView`가 진입 카메라를 덮어쓰지 않도록 모드를 구분합니다.
탭을 다시 활성화했을 때는 경과 시간을 기준으로 완료하며 콜백은 한 번만 실행합니다.

## 5. 연결 계약과 상태

`LandingPage`에 다음 연결 계약을 추가할 예정입니다.

```ts
type DashboardEntry = {
  source: "flower";
  result: DeployResult | null;
};

type LandingProps = {
  onComplete?: (result: DeployResult) => void;
  onEnterDashboard?: (entry: DashboardEntry) => void | Promise<void>;
};
```

상태 흐름은 `idle → zooming → entering`이며, 미연결·연결 실패 시
`returning → idle`로 복귀합니다.

- 줌 중 연속 클릭은 무시하고, 폼·다시 배포하기도 잠시 비활성화합니다.
- `zooming` 중 Escape로 취소하면 원래 카메라와 UI로 복귀합니다.
- 연결 콜백 호출 후에는 Escape로 이미 시작된 이동을 취소하지 않습니다.
- 콜백이 실패하면 안내를 표시하고 복귀합니다. 배포 결과는 유지합니다.
- 콜백이 정상 종료됐지만 페이지가 여전히 마운트되어 있다면 복귀합니다.
  외부 앱의 비동기 이동은 콜백이 해당 작업을 기다리는 Promise를 반환합니다.
- 연결 후 라우트 이동으로 언마운트되면 기존 `dispose()`가 RAF·GPU 자원을 해제합니다.
- 언마운트 후 콜백 실행이나 상태 갱신이 없도록 전환을 취소합니다.

### 나중에 연결하는 방법

- 같은 Next.js 앱: 별도 client 연결 컴포넌트에서 `next/navigation`의
  `router.push(확정된 경로)`를 호출합니다. 목적지 라우트를 추가한 뒤 연결합니다.
- 외부 `lily-dashboard` 앱: 확정된 URL로 이동하는 콜백을 주입합니다.
- 경로·URL은 연결 컴포넌트가 소유합니다. Three.js 씬은 라우터를 알지 않습니다.
- `slug`만으로 프로젝트를 식별하지 않습니다. 실제 대시보드의 프로젝트 ID·인증·
  상태 복원 방식은 연동 시 결정하며, 현재 배포 시뮬레이션 결과는 참고 정보입니다.

## 6. 클릭 영역과 접근성

- **사용자 승인 대안:** 꽃 클릭 영역 때문에 폼 조작이나 모바일 레이아웃이 불안정해지면
  꽃 클릭을 제거하고 “다시 배포하기” 옆에 “대시보드로 이동” 버튼을 배치합니다.
  버튼도 동일한 꽃술 확대와 `onEnterDashboard` 연결점을 실행합니다.
  모바일에서 가로 공간이 부족하면 버튼을 세로로 배치합니다.
- 버튼 방식에서는 배포 전에도 진입할 수 있도록 폼 아래에 같은 버튼을 두고,
  배포가 끝나면 결과 액션 영역으로 옮깁니다. 배포 진행 중에는 비활성화합니다.
- 먼저 꽃 클릭 영역을 적용하고 폼·내비·모바일 터치 영역과 충돌하는지 확인합니다.
  충돌을 피하기 위해 복잡한 레이아웃 보정이 필요하면 버튼 방식으로 전환합니다.
- 전체 화면 캔버스에 클릭 핸들러를 붙이지 않습니다. 폼·내비 조작을 유지합니다.
- 꽃의 투영 영역을 기준으로 버튼 위치와 크기를 계산하고, 가시 꽃과 맞는 둥근 영역으로
  조정합니다. 투명 사각형이 빈 배경까지 넓게 덮지 않도록 실제 화면에서 확인합니다.
- 버튼 이름은 “꽃을 눌러 대시보드로 이동”으로 제공하고 포커스 테두리를 표시합니다.
- 꽃 아래에 짧은 안내를 두어 모바일에서도 클릭 기능을 발견할 수 있게 합니다.
- 랜딩을 숨길 때 opacity만 줄이지 않고 키보드·보조기술의 접근도 함께 막습니다.
  전환 취소·복귀 시 원래 포커스를 복원합니다.
- `prefers-reduced-motion`에서는 확대를 생략하고 연결점을 바로 실행합니다.
- WebGL 오류·마스크 로딩 실패 시에도 대체 버튼으로 진입할 수 있습니다.

계획 문서는 이번에 작성하고, 구현은 검토 이후 진행합니다.

## 8. 구현 확인 기준

확인 항목은 아래와 같습니다. 자동 테스트 추가·실행은 별도 요청이 있을 때 진행합니다.

- 데스크톱·모바일에서 꽃술이 화면 중앙으로 확대되고 마지막 프레임이 자연스럽게 감춰짐.
- 꽃 클릭 영역이 레포 입력·배포 버튼·내비를 가리지 않음.
- 연속 클릭·Enter 반복에도 연결 콜백은 한 번만 실행됨.
- 성공·롤백 결과를 유지하며 전환하고, 배포 중에는 진입하지 않음.
- Escape 취소·미연결·콜백 실패 시 카메라와 포커스가 복구됨.
- reduced motion·WebGL 실패에서도 같은 연결점에 접근 가능함.
- 줌 중 resize·언마운트에도 루프·컨텍스트 누수가 없음.

## 9. 범위 변경

기존 [PLAN.md §5.4](./PLAN.md)의 “연결 지점만 열어두고 화면을 만들지 않는다”는
원칙은 유지합니다. 이번 문서는 여기에 **사용자 클릭과 꽃술 확대 연출**을 추가합니다.
실제 목적지 경로가 확정될 때까지 대시보드 라우트는 생성하지 않습니다.
