# 언어 설정

## 사용 방법

- 기본 언어는 한국어입니다. 브라우저 언어를 자동으로 적용하지 않습니다.
- 상단 지구본 메뉴에서 한국어, English, 日本語를 선택합니다.
- `lily-locale` 쿠키에 1년간 저장하며 새로고침과 페이지 이동에도 유지합니다.
- 프런트와 대시보드가 같은 공개 주소이면 쿠키를 공유합니다.
- 공개 주소가 서로 다르면 이동 링크의 `lang=ko|en|ja`로 설정을 전달합니다.
  각 앱의 `proxy.ts`가 유효한 값만 쿠키에 저장하고 `lang`만 제거합니다.
  기존 `project`, `next`, `cursor` 등의 파라미터는 유지됩니다.
- 다른 브라우저나 기기는 각각 한국어로 시작합니다. 계정 DB에 저장하는 설정은 아닙니다.

## 번역 추가

`lib/i18n`에 i18next 설정과 영어(`en.json`), 일본어(`ja.json`) 사전이 있습니다.
프런트에서는 `src/lib/i18n` 경로를 사용합니다. 한국어 원문을 키로 사용합니다.

```tsx
// 클라이언트 컴포넌트
const { t, locale } = useI18n();
return <button>{t("로그인")}</button>;
```

```tsx
// 서버 컴포넌트: 서버 전용 코드와 API 키는 클라이언트로 옮기지 않습니다.
const t = await getTranslator();
return <h1>{t("내 프로젝트")}</h1>;
```

- 새 문구를 영어·일본어 사전에 함께 추가합니다. 한국어는 원문 키를 사용합니다.
- 변수는 `{{value0}}` 같은 보간 키로 정의하고 `t(key, { value0: value })`로 전달합니다.
- 프런트와 대시보드의 공통 문구를 수정할 때는 두 저장소 사전을 함께 갱신합니다.
- API 상태 코드, 폼 필드명, 환경변수 키, URL은 번역하지 않습니다.
- 사용자 프로젝트 이름·레포 주소·빌드/실행 로그는 원문으로 표시합니다.
- 서버의 정해진 안내 문구는 화면에서 번역하고, 사전에 없는 응답은 원문을 유지합니다.
- `localeLink(destination, locale)`로 앱 간 이동 링크를 만듭니다.
- 서버에서는 요청마다 i18next 인스턴스를 생성해 다른 사용자의 언어가 섞이지 않게 합니다.
